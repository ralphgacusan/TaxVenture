## 1. What this documentation does

Records the story approved in the planning conversation, including the subsequent name/identity choices and the user's final request for all solved clients to be acknowledged in the endings. It preserves unresolved details explicitly rather than filling them with assumed canon.

It does not implement any scene, case, quest, reward, save field or ending. It does not replace financial fixtures, validate real tax law, reset progress, authorize Git operations or create implementation tickets.

## 3. Explicit revisions and common misunderstandings

1. **One continuing case, not unrelated second cases every chapter.** Bayview is the same retained file from Level 2 through Level 5.
2. **No independent calculation lesson in Level 1.** User's casual calculation example did not revise the documented learning sequence. L1 classification, L2 income verification, L3 deductions/calculation, L4 returns/versions, L5 integrated review.
3. **Apply last lesson first.** Bayview's stages are L2 classification, L3 income, L4 expenses/computation, L5 return/investigation. Do not restore the earlier accelerated clue schedule.
4. **Nina moves to Level 4 in this target.** The older deferred L3 Marine Services case is not an active second case in Bea's chapter. Its tax fixtures are not automatically the new return-preparation packet.
5. **Marine Services is legitimate.** It is neither Bayview nor the redevelopment antagonist. Nina cooperates; do not make her company suspicious merely to connect plots.
6. **The corporation itself is antagonist.** Not just one company leader. Adrian knowingly represents pressure, with company authority established through evidence.
7. **Official service name is CoastCare Tax Assistance.** “Tulong Desk” was rejected. Old generic Assistance Desk references describe its antecedent role but are not the approved final name.
8. **Male bookkeeper Marco Ramos.** The initial Liza Ramos suggestion was replaced. Adrian is male; letter author Mang Kanor is male.
9. **Aling Lorna is not the letter author.** She remains an existing ambient resident. Kanor's repair shop supplies the letter context.
10. **Existing chest style reused.** Do not replace it with a newly invented weathered-storage-chest system. New location/contents are planned; exact location is open.
11. **CT-07 is recognition, not proof.** Required ownership/authorization records establish the actual relationship and conduct.
12. **Bayview interim reviews have no delivered copy.** Auditor retains stage; receptionist returns file with records next chapter. Main clients keep follow-through.
13. **Accepted stage / open case.** Repeated Not Ready was a user suggestion that was refined; do not present correct stages as failures.
14. **Paper Trail belongs to L4; Catch Me If You Comply belongs to L5.** A proposed differently named L5 paper-trail activity was not adopted. Their precise mechanics remain open.
15. **Quax remains mayor, Arthur remains guide.** No reverted Quax tutorial/demo system is reinstated by this story.
16. **Two endings remain conditional on evidence and trust.** Do not make mastery first-check score a third victory requirement. Do not make high popularity override knowingly suppressed evidence.
17. **Winning allows fair development.** The harmful corporate agreement is rejected, not all future improvement.
18. **Client outcomes matter in both endings.** The final user correction specifically includes cases solved across levels, including Bea and Rosa, alongside Kanor/waterfront.
19. **No obligatory shop purchases.** Base tools and references must suffice. Optional equipment can support presentation without gating learning or victory.
20. **Cutscene sample dialogue is not canon.** Start/end duration direction is approved; actual scripts/shot plans remain future work.

## 6. Implementation continuity principles

These retain existing project context rather than inventing new systems:

- Preserve existing office/plaza, paper handling, Case Folder, book, annotations, calculator, stamps, Auditor conversation, Bag and Client Copy interactions where applicable.
- Previously acquired campaign possessions remain owned across chapters under the established continuation rule. Current-case validity is not permission to delete prior items.
- Retained records can be read without accidentally transferring another client's values into current work. Narrative continuity does not authorize a new universal archive framework.
- Do not double-award existing service/ethics rewards for a new recap or repeated review.
- Preserve actual saved choices and accepted stage work; a next-level file return is continuation, not a fresh reset.
- Keep optional purchases optional, and the deferred comparison stand deferred unless separately authorized.
- Existing numerical examples are not current tax-law certification. New financial content needs the relevant educator/source validation process.
- Inspect active implementation before claiming a sequence is missing or complete. The planning conversation's earlier “unfinished delivery” statements are historical snapshots, not live status checks.

## 7. Next-agent procedure and completion boundaries

### For story discussion

Read README and the document matching the requested topic. Treat settled names/roles/level order as settled; ask only for open decisions relevant to the task. Do not restart the entire interview or reintroduce rejected alternatives without a concrete conflict.

### For detailed specification

Read LEVEL_FLOW, MYSTERY_AND_EVIDENCE and CHOICES_TRUST_AND_ENDINGS, then inspect applicable active level contracts. Resolve exact source/evidence/approval/trust questions before writing final scripts or fixtures. Completion means a reader can identify the current task, evidence-supported output, next handoff and actual consequences without guessing.

### For implementation

Obtain the user's implementation scope and follow applicable repository/initiative instructions. This documentation request alone is not that scope. Reuse existing systems and preserve historical implementation evidence. Validate source and behavior appropriately; rendered/device acceptance remains distinct.

### Before calling the campaign production-ready

- Every stage has an authored source packet and supported answer key.
- Each accusation has adequate original/version/authorization evidence.
- The fictional approval/support mechanism is understandable and consistent.
- Numeric trust paths establish reachable, fair outcomes and finite recovery.
- All main client delivery and continuing Auditor handoffs work without duplicated ownership/rewards.
- Optional clue absence does not block either legitimate progress or a supported victory.
- L4/L5 gameplay is specified and connected to the learning progression.
- Final scenes acknowledge all intended clients without undoing their corrected cases.
- Applicable internal verification and user visual/device acceptance are separately recorded.

No checklist item is satisfied solely by its inclusion in this document.
